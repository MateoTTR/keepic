TASK-021 — Implement manual re-index of library folder

## Goal
Expose the existing library indexer to the user via a "Re-index library" button. The entire backend (runIndexer, worker, IPC channels, preload bridge) was already implemented in TASK-006 — this task is UI-only.

## Architecture decisions

### UI-only task
No new backend code, no new IPC channels, no new tests. All non-frontend coverage remains at 100% (317 tests unchanged).

### 4-state ReindexScreen
The screen handles all cases from the existing `StartIndexResult` contract:
- `starting` — awaiting the `startIndex()` reply
- `running` — receiving `onIndexProgress` push events (processed/total count)
- `done` — `onIndexComplete` with `type: 'complete'` (indexed/skipped/deleted summary)
- `error` — either `startIndex()` returns `{ error }` or `onIndexComplete` with `type: 'error'`
- `alreadyRunning` — `startIndex()` returns `{ alreadyRunning: true }`

### Back button disabled while running
The Back button uses `disabled={!done}` where `done` is a `$derived` that is true for all terminal states. This prevents the user from navigating away mid-scan (the worker would continue but progress events would be missed).

### Stats auto-refresh on return
When the user clicks Back after a successful re-index, `handleReset` in `App.svelte` sets `currentScreen = 'home'`, which destroys and recreates `HomeScreen` (Svelte `{#if}`), triggering its `onMount` stats fetch automatically.
