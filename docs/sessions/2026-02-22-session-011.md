# Session 011 — 2026-02-22

## Task
TASK-013 — Google Photos media fetch, date filter, and download

## Goal
Implement the Google Photos download phase: fetch photos from the Google Photos Library API for a date range, download them to a local temp folder, then feed that folder into the existing local import pipeline (plan → review → execute).

## Architecture decisions

### Two-phase pipeline
The user revised the original single-phase streaming approach in favour of a clean two-phase separation:
- **Phase 1 (new)**: Download only — fetch all photos for the selected date range and save them to `userData/temp/google-<timestamp>/`. No analysis, no DB writes during download.
- **Phase 2 (existing)**: Pass the temp folder through the unchanged local import pipeline. pHash deduplication handles photos that were previously imported manually from Google Photos (no `google_id` in DB).

### Token boundary
Main process reads `StoredTokens` from keytar and passes them to the worker as `DownloaderTokens`. The worker performs HTTP-only token refresh (no keytar access). On completion, the worker returns `updatedAccessToken` / `updatedExpiresAt` to main, which persists them back to keytar.

### Incremental sync
`last_imported_date = today` (not the last photo's date) is stored in `import_jobs` (source='google_photos', status='completed') after a successful download. The date picker is pre-filled with this value on next import. The user can still adjust the date manually.

### `google_id` not stored
Accepted trade-off: re-importing the same date range re-downloads files, but pHash in Phase 2 catches duplicates correctly.

### Temp folder
`userData/temp/google-<timestamp>/` — created per download session, cleaned up when the user resets to the home screen.
