## Task

**TASK-051-fix** — Upgrade libheif 1.17.6 → 1.21.2 to fix Apple HDR HEIC decode failure

## Context

v0.3.2 manual testing revealed ~85 HEIC files from iOS 18+ failing with:
`"Too many auxiliary image references (2, 0)"`. These are Apple HDR photos with gain map auxiliary images. libheif 1.17.6 rejects files with more than one auxiliary image reference. Fixed in libheif 1.18.0+.

## Key Findings

- **C++ API unchanged**: `heif_cxx.h` API (Context, get_primary_image_handle, decode_image, get_plane) is identical between 1.17 and 1.21 — zero code changes needed in `heif-decode.cc`
- **CMake restructure in 1.19+**: libheif now uses a `plugin_option()` macro system with many codecs ON by default (x265, x264, AOM, OpenH264). Must explicitly disable all except de265.
- **New CMake flags added**: `ENABLE_PLUGIN_LOADING=OFF` + 16 `WITH_*=OFF` flags to keep only HEVC decoder
- **libde265 1.0.15 still compatible** — no upgrade needed
- **Static library names unchanged** (`libheif.a`/`heif.lib`, `libde265.a`/`libde265.lib`)
- **CI OOM on Linux**: libheif 1.21.2 has ~87 C++ source files — unlimited `--parallel` exceeded 7 GB RAM on GitHub runner. Fixed with `--parallel 2`.
