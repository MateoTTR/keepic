# Session 039 — 2026-03-07

## FEAT-001: Duplicate Photo Viewer with Thumbnails (PR #46)

### Summary

Implemented visual duplicate comparison with thumbnail previews for both the import review screen and the standalone deduplication scan. Added "Reveal in Folder" button to open photos in the OS file explorer.

### What was done

**Backend (FEAT-001a):**
- Custom Electron protocol `keepic-photo://` via `protocol.handle()` to serve resized JPEG thumbnails (300px max) to the sandboxed renderer
- `createThumbnailGenerator({ decodeFn? })` factory with injectable `HeicDecodeFn` — same pattern as `createHeicConverter` and `createUniversalPhashComputer`, ready for POC-001 native decoder swap
- Shell IPC handlers (`shell:reveal-in-folder`, `shell:reveal-library-file`) wrapping `shell.showItemInFolder()`
- `protocol.registerSchemesAsPrivileged` at top level (before `app.ready`)

**Frontend (FEAT-001b):**
- `PhotoThumbnail.svelte` component with loading spinner + error fallback ("Preview unavailable")
- `ReviewScreen`: side-by-side thumbnails in expanded duplicate row (source vs library match) with metadata + "Reveal in Folder"
- `DeduplicationScreen`: thumbnail grid per duplicate group with "Reveal in Folder" per photo
- `thumbnailUrl()` helper for building `keepic-photo://` URLs with proper encoding

**Documentation:**
- Updated specs (§2.5.1 Duplicate Viewer)
- Updated architecture (§3.1 custom protocol for image display)
- Updated backlog (Phase 13)
- Created task file `FEAT-001a-thumbnail-protocol.md`

### Key Design Decisions

1. **Custom protocol over base64 IPC** — no 33% overhead, browser-native caching, CSP-compatible
2. **On-the-fly resize, no disk cache** — JPEG ~5ms, HEIC ~400ms, acceptable for comparing 2-4 photos
3. **Injectable HEIC decoder** — `HeicDecodeFn` type, defaults to WASM, swappable to native when POC-001 delivers
