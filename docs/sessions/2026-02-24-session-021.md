## TASK-030 — Fix structured clone error breaking local import (PR #27)

### Root cause

`ExecutionScreen.svelte` passes the `plan` prop directly to Electron IPC via
`window.keepic.import.execute(plan)`. In Svelte 5, props from `$props()` are deep reactive
Proxies. Electron's IPC uses the Structured Clone algorithm, which cannot serialize Proxy
objects, causing:

```
Uncaught (in promise) Error: An object could not be cloned.
```

The `.catch()` handler (added in TASK-029) converts this to `{ error }` and calls
`onComplete` with `status: 'failed'`, so the user sees 0 files imported.

### Changes

1. **`src/renderer/src/screens/ExecutionScreen.svelte`** — Wrap `plan` with
   `$state.snapshot(plan)` before passing to IPC. This unwraps the Proxy into a plain
   object that can be structured-cloned.

2. **`src/main/google-photos-downloader.ts`** — The 403 PERMISSION_DENIED handler now
   forwards Google's actual `error.message` (e.g., "Request had insufficient authentication
   scopes.") instead of a hardcoded string.

3. **`tests/main/google-photos-downloader.test.ts`** — Updated existing 403 test to match
   new message format. Added test for 403 PERMISSION_DENIED without a message field.

## Bug 2 — Google Photos Library API deprecated (no code fix possible)

### Investigation

1. Initial hypothesis: Google Cloud project in "Testing" mode → switched to "In Production" → still 403
2. Confirmed: user email is in test users, scope is granted, API is enabled
3. Improved error message (PR #27) revealed Google's actual response:
   `"Request had insufficient authentication scopes."`
4. Web research revealed this is a **platform-wide deprecation**

### Root cause

Google **deprecated the `photoslibrary.readonly` scope on March 31, 2025**. All API calls
using `mediaItems:search` with this scope now return 403 PERMISSION_DENIED. This affects
all third-party apps globally (confirmed: rclone, n8n, Make, custom apps).

The replacement is the **Google Photos Picker API** — a user-driven selection interface
instead of programmatic access to the full library.

References:
- [Updates to the Google Photos APIs](https://developers.google.com/photos/support/updates)
- [Picker API launch announcement](https://developers.googleblog.com/en/google-photos-picker-api-launch-and-library-api-updates/)

### Decision

Migrate to the Picker API. The user selects photos via a Google-hosted UI (supports
selection by day). The two-phase pipeline (download → local import) is preserved.
