## TASK-036 — Fix HEIC import decoding failure (PR #28)

### Root cause

sharp@0.33.5's prebuilt binaries **do not include the HEVC/H.265 decoder** (libde265)
due to patent licensing. The bundled libheif only supports AV1/AVIF decoding:

- `sharp.format.heif.input.fileSuffix` → `[".avif"]` only (no `.heic`/`.heif`)
- This fails in both dev mode and packaged app — not an Electron packaging issue

### Solution

Two-step pipeline replacing the single `sharp(src)` call:

1. **Decode**: `heic-decode` (npm) — WebAssembly port of libde265 via `libheif-js`.
   The WASM binary is inlined in a bundle.js (no external `.wasm` file), so it works
   seamlessly inside Electron's asar archive.

2. **Encode**: `sharp` — receives raw RGBA pixels, encodes to JPEG with mozjpeg quality
   control.

### Changes

1. **`package.json`** — Added `heic-decode@^2.0.0` dependency (pulls in `libheif-js`).

2. **`src/main/heic.ts`** — New `createHeicConverter()` factory function with injectable
   `HeicPixelDecoder` and `readFile` parameters. `defaultHeicConverter` is now created
   via `createHeicConverter()` with real `heic-decode`.

3. **`src/main/heic-decode.d.ts`** — TypeScript type declarations for `heic-decode`
   (no `@types` package available).

4. **`tests/main/heic.test.ts`** — Rewritten to use injectable mock decoder for the
   decode step (real HEIC test fixtures not feasible without an encoder). 6 new tests
   for `createHeicConverter`: valid pipeline, buffer passing, quality parameter,
   missing file, decoder error, custom readFile.

### EXIF metadata note

The output JPEG does not embed EXIF metadata. This is acceptable because the import
pipeline stores all metadata (date_taken, GPS, dimensions) in SQLite via `exifreader`
before conversion. Users relying on EXIF in the library folder files will not see it
in converted HEICs — this is a known trade-off documented in the task file.
