# Session 063 — 2026-10-11

First session in seven months (previous: session 062, 2026-03-10, v0.5.8).

## Tasks

### TASK-071-fix — macOS "Malware Blocked and Moved to Trash"
- **Status**: Completed (PR #95)
- **Report**: a macOS user could no longer launch KeePic v0.5.8. The dialog read "Logiciel malveillant bloqué et placé dans la corbeille", and `xattr -cr /Applications/KeePic.app` no longer helped.
- **Root cause**: an Apple XProtect signature update (definitions ~5358, around 2026-05-29) falsely flags the **Electron 31.7.7** binary. `^31.0.0` always resolves to 31.7.7. The match is on file contents, so re-signing does not help either. The same false positive was reported in asivery/ElectronWMD#61 and a-ch3n/holobooth@63917d2.
- **Fix**: Electron `^31.0.0` → `^32.0.0` (32.3.3). Electron 32's breaking changes were reviewed; none affect KeePic.

### TASK-072-fix — HEIF deps cache never available to release builds
- **Status**: Completed (PR #96)
- **Root cause**:
  - Tag-triggered releases can only restore `main`-scoped caches, and the warm-up workflow had never reached `main`.
  - GitHub evicts caches after 7 days without access.
  - `restore-keys` could restore deps built by an older `build-deps.sh`.
- **Fix**:
  - Warm-up runs on every push to `main`, on a Mon+Thu cron, and on dispatch. It does a full restore to refresh the access time.
  - Releases restore by exact key only.
- **CI install fix**: `ci.yml` lacked `apt-get update`. A stale runner index (libde265 404) was failing **every** CI run.
- **Validated** on the first v0.5.9 tag: both platforms logged a cache hit and skipped the deps build.

### TASK-073-fix — First v0.5.9 release failed on Windows
- **Status**: Completed (PR #98)
- **Symptom**: electron-builder's `npm rebuild @keepic/heif-decode` fell back to a source rebuild with npm's bundled node-gyp 10.1.0. That version cannot find **Visual Studio 2026**, which `windows-latest` has used since June 2026, and it would not have built statically anyway.
- **Fix**:
  - `node-gyp@12.4.0` devDependency and a `build:heif-static` script
  - `npm_config_heif_static=true` on packaging, so any rebuild is static
  - "Verify packaged HEIF addon" step: dumpbin/otool dependency check plus HEIC smoke test
  - `workflow_dispatch` dry runs of `release.yml` (`create-release` runs only for tags)
  - `CMAKE_OSX_DEPLOYMENT_TARGET=12.0` for the static HEIF deps (`macos-latest` is macOS 26; the linker emitted 40 warnings)
- The v0.5.9 macOS DMG from the failed run was inspected with 7-Zip and a Mach-O parser: static addon, `minos` 12.0, only `libSystem`/`libc++`.

### TASK-075-fix — VS 2026-built addon fails DLL init on some machines
- **Status**: Completed (PR #100)
- **Symptom**: a second dry run failed at the new verification step with "A dynamic link library (DLL) initialization routine failed". The first dry run had passed with an identical binary.
- **Investigation**: a temporary diagnostic workflow built the addon with VS 2026 and with VS 2022, then loaded each 3 times on 8 runners.
  - VS 2022: **24/24** loads OK.
  - VS 2026: 2 of 8 machines failed every time.
  - The failing machines were indistinguishable from passing ones (same CPU, OS build, image version, mitigations).
  - This also caused the original v0.5.9 failure: `node-gyp-build`'s load test rejected the addon.
- **Fix**: Windows release, cache warm-up and prebuild workflows pinned to `windows-2022`. The cache key names the toolchain.

## Findings

- **The repository is public**, so GitHub Actions minutes are free.
- **Runner drift is the main release risk**: `windows-latest` (VS 2026) and `macos-latest` (macOS 26) both changed under us. Windows is now pinned to `windows-2022`, and macOS deps have an explicit deployment target.
- **A single green smoke test does not prove a Windows toolchain is safe**. The VS 2026 build passed on 6 of 8 machines.
- **Local toolchain drift**: the WSL shell defaults to Node 24 (npm 11), while CI uses Node 20 (npm 10).
  - Run tests with `nvm exec 22`.
  - npm 11 lockfiles break `npm ci` in CI.
- Local `npm run lint` reports parsing errors from untracked CMake artifacts in `packages/heif-decode/deps/`. CI is unaffected.
