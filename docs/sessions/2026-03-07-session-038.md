### Performance Observations

| Operation | Duration | Details |
|---|---|---|
| Re-index (1018 photos, 703 HEIC) | 6m52 | ~400ms/HEIC file (WASM sequential) |
| Planner — JPEG only (45 photos) | 646ms | ~14ms/photo — sharp native, non-blocking |
| Planner — mixed (420 photos, 402 HEIC) | 3m33 | ~507ms/HEIC — heic-decode WASM blocks event loop |
| Executor — move only (303 photos) | 690ms | Instant — file moves, no decoding |

**Key finding**: HEIC WASM decoding (~400-500ms/file) is 30-40x slower than JPEG processing (~14ms/file). `withConcurrency` (PERF-001) provides no benefit for HEIC because WASM blocks the V8 event loop — all decodes are effectively sequential regardless of concurrency setting.

### Conclusion

All Phase 10 features work correctly. The HEIC decoding bottleneck is the primary performance issue. A Proof of Concept comparing native decoding strategies (libheif C addon, sharp+HEVC rebuild, etc.) is the recommended next step before implementing PERF-002.
