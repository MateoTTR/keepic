## TASK-029 — Fix import worker robustness (PR #25)

### Changes

1. **`src/workers/importer.worker.ts`** — Wrapped synchronous `db.open()` in try-catch.
   Initialization errors are now reported via `postMessage({ type: 'error' })` before
   `process.exit(1)`, instead of crashing silently.

2. **`src/main/ipc/import-handlers.ts`** — Added `worker.on('exit')` handler in
   `handleExecute`. If the worker exits without having sent `complete` or `error`,
   `onComplete` is called with `status: 'failed'`. The guard
   `activeWorkerRef.value === worker` prevents double `onComplete` calls.

3. **`src/renderer/src/screens/ExecutionScreen.svelte`** — `execute()` return value is
   now handled instead of being silently discarded with `void`. Both `{ alreadyRunning }`
   and `{ error }` results are surfaced to the UI.

4. **`src/main/ipc/google-photos-handlers.ts`** — Added the same `worker.on('exit')`
   handler in `handleStartDownload` (same vulnerability pattern).

### Tests added

- Worker exits without sending any message → `onComplete` called with `status: 'failed'`
- Worker exits after `complete` → `onComplete` NOT called twice
- Worker exits after `error` event → `onComplete` NOT called twice
- Same 3 tests for Google Photos `handleStartDownload`

## TASK-028 — Fix Google Photos scope verification (PR #26)

### Changes

1. **`src/main/google-auth.ts` — `startOAuthFlow`** — After token exchange, verify
   granted scopes using full URL matching (`Array.includes` on `scope.split(' ')`). If
   `photoslibrary.readonly` is absent, throw immediately before storing the token.

2. **`src/main/google-auth.ts` — `getValidAccessToken`** — On token refresh, if the
   response includes a `scope` field without `photoslibrary.readonly`, delete stored
   tokens and return `null`. If no `scope` field is present (Google doesn't always include
   it on refresh), the token is accepted.

3. **`tests/main/ipc/google-auth-handlers.test.ts`** — Updated existing mock to include
   `scope` in token response.

### Tests added

- Token exchange without `photoslibrary.readonly` → error thrown
- Token exchange with no `scope` field → error thrown
- Token exchange with similar scope (`photoslibrary.readonly.limited`) → error thrown
- Refresh with valid scope → token returned
- Refresh with revoked scope → `null` returned, tokens deleted
- Refresh without scope field → token accepted
