# Session 060 — 2026-03-10

## Task

**TASK-068-fix** — Fix dedup lazy rendering (IntersectionObserver not working, UI freezes at ~320 groups)

## Root cause analysis

Deep code review of the dedup rendering pipeline identified 5 interacting issues:

1. **Thumbnail flood**: 320 groups x ~3 photos = ~960 `keepic-photo://thumbnail` requests hitting the main process simultaneously, each triggering `sharp().resize()` on the libuv thread pool (4 threads default).
2. **320 IntersectionObservers**: Each `LazyGroup` created its own observer instead of sharing one.
3. **Layout cascade**: Switching from 280px placeholder to real content triggered reflow → observer callbacks on adjacent groups → chain reaction.
4. **`loading="lazy"` broken**: Tabbed UI (TASK-059) changed layout structure, preventing Chromium from correctly calculating off-screen positions.
5. **No thumbnail cache**: Every screen open regenerated all thumbnails via sharp.

## Changes

### DeduplicationScreen rewrite
- **Collapsed-by-default groups**: all groups render as compact text rows (filename, count, media type) — trivial DOM cost even at 600+ groups
- **Click to expand**: each group has a toggle button to show/hide thumbnails
- **Expand all / Collapse all**: bulk actions for convenience
- **SvelteSet**: uses `SvelteSet` from `svelte/reactivity` for reactive expand/collapse state (required by `svelte/prefer-svelte-reactivity` lint rule)

### Thumbnail concurrency throttle
- New `createThrottle(maxConcurrent)` utility in `protocol.ts`
- Protocol handler limited to 6 concurrent `sharp()` operations (was unlimited)
- Queue-based: excess requests wait until a slot opens

### Cleanup
- Deleted `LazyGroup.svelte` (IntersectionObserver wrapper that never worked)
- Removed pagination ("Show more" button) — no longer needed with collapsed groups

## Lessons learned

- **`svelte/prefer-svelte-reactivity`**: Svelte 5 eslint rule requires `SvelteSet`/`SvelteMap` instead of native `Set`/`Map` for reactive state in components. Mutations on `SvelteSet` are automatically tracked — no need to reassign.
- **IntersectionObserver is overkill for this use case**: collapsed-by-default with on-demand expansion is simpler, more predictable, and works regardless of scroll container setup.
