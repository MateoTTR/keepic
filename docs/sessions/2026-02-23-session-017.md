## Setup findings

### Node.js on Windows
- Node.js installer for Windows includes an optional step to install Python + Visual Studio
  Build Tools (needed for native modules: `better-sqlite3`, `keytar`).
- `sharp` v0.33+ uses prebuilt `@img/*` binaries independent of the Node.js/Electron ABI —
  no rebuild needed.
- `better-sqlite3` and `keytar` need `npx @electron/rebuild` after `npm install` to match
  Electron's ABI (Electron 31 embeds Node.js 20, system is Node.js 22 → ABI mismatch).
- VS Code integrated terminal does not inherit the updated PATH from a fresh install;
  launch VS Code with `code .` from a new PowerShell terminal, or restart the machine.

## Bug #1 — Workers never compiled (TASK-023, PR #20)

### Symptom
`Cannot find module '...out/workers/indexer.worker.js'` when triggering re-index, local
import, or Google Photos import.

### Root cause
`electron.vite.config.ts` declared only `src/main/index.ts` as the main process entry.
Worker files in `src/workers/` are referenced by path string (not `import`), so Rollup
never discovers them. All four workers were never compiled — in dev mode AND in production
builds (v0.1.0 and v0.1.1 releases were also affected).

### Fix
- Add all 4 workers as `build.rollupOptions.input` entries in the `main` config
  (key format `'workers/foo.worker'` → output `out/main/workers/foo.worker.js`)
- Update 4 path references in `src/main/index.ts` from `'../workers/'` to `'workers/'`

## Bug #2 — OAuth callback server crash + "fetch failed" (TASK-024, PR #21)

### Symptom
After authorizing Google Photos in the browser, a crash dialog appeared:
`TypeError: Cannot read properties of null (reading 'port')`. Then the UI showed
"fetch failed".

### Root cause
The OAuth callback HTTP server called `server.address()` on the first line of every
request handler. After the first valid callback request, `server.close()` was called,
setting the internal handle to null. The browser then sent a second request (`/favicon.ico`),
causing `server.address()` to return null → uncaught TypeError. Electron surfaces uncaught
main-process exceptions as a synchronous modal dialog, which blocked the Node.js event
loop while the token exchange fetch was pending → fetch failed.

### Fix
Replace `(server.address() as { port: number }).port` with `req.socket.localPort!` —
reads the port from the incoming TCP socket, always available regardless of server state.

## UX #1 — No guidance to index library after first configuration (TASK-025, PR #22)

### Symptom
After configuring the library folder, the SQLite index is empty. Importing without
re-indexing first causes all photos to appear as "new" even if they already exist in the
library, potentially creating duplicates.

### Fix
Add an amber warning banner in `HomeScreen.svelte` shown when `libraryPath` is set and
`stats.totalPhotos === 0`. Banner disappears automatically after re-indexing completes.
