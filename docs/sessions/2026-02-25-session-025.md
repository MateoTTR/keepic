## Key Design Decisions

### Two-phase download
- Phase 1: paginate through all `listPickerMediaItems` pages to collect the full item list (so `total` is known upfront before any download begins)
- Phase 2: sequentially download each item via `baseUrl + '=d'` (original quality)
- This gives accurate `{ total, downloaded, currentFile }` progress events

### Token refresh
- `refreshAccessToken` is a standalone helper (testable independently)
- `downloadPickerPhotos` catches "Token expired" during Phase 1, refreshes, and retries once
- If a refresh occurred, `updatedAccessToken` and `updatedExpiresAt` are returned in the result
- `spawnPickerDownloadWorker` calls `updateStoredAccessToken` automatically on completion when a refreshed token is present

### Injectable dependencies pattern
- `DownloaderDeps`: `fetch`, `writeFile`, `mkdirp`, `isCancelled`, `listMediaItems`
- `StartPickerDownloadDeps`: `authDeps`, `createWorker`, `getTokens`
- All external boundaries mockable; no mocking of internal modules

### Filename collision resolution
- `resolveFilenameCollision(filename, usedFilenames)` appends `_1`, `_2`, ..., `_99`, then timestamp fallback
- Operates on a `Set<string>` built per-session (not persisted)

### Handler split
- `spawnPickerDownloadWorker` (sync) — takes pre-fetched tokens, wires up worker events, exported for direct testing without async token fetching
- `handleStartPickerDownload` (async) — guards against double-start, calls `getStoredTokensForDownload`, then delegates to `spawnPickerDownloadWorker`
