# Session 036 — 2026-03-07

## Tasks: TASK-041 + TASK-042 (Phase 10, P0 bug fixes)

### Summary

Implemented the two P0 bug fixes identified during the v0.2.2 manual testing session (session 035).

### TASK-041 — Fix missing progress during Phase 1 (PR #42)

**Problem**: After PERF-001 introduced the two-phase pattern, `onProgress` was only called during Phase 2 (sequential DB writes). The UI stayed stuck on "Starting..." for the entire duration of Phase 1 (parallel pHash + EXIF extraction).

**Fix**:
- Send initial progress event `{ total, processed: 0 }` immediately after scan
- Report per-file progress during Phase 1 via a shared counter in the `withConcurrency` callback
- Applied to all three functions: `runIndexer`, `buildImportPlan`, `executeImportPlan`
- JS single-threaded guarantee makes the shared counter safe between `await` points

**Files**: `indexer.ts`, `importer.ts`, `indexer.test.ts`, `importer.test.ts`

### TASK-042 — Fix Google Picker HEIC served as JPEG (PR #43)

**Problem**: Google Picker API (`baseUrl=d`) converts HEIC to JPEG server-side but preserves the original `.HEIC` filename. The import pipeline tried HEIC decoding on JPEG data, causing pHash failure: "input buffer is not a HEIC image".

**Fix**:
- Added `isJpegBuffer(data)` — checks first 3 bytes for JPEG magic `FF D8 FF`
- Added `fixHeicJpegExtension(filename, data)` — renames `.heic`/`.heif` → `.jpg` when content is JPEG
- `downloadMediaItem` now returns the `Buffer` for post-download inspection
- Added `renameFile` to `DownloaderDeps` for injectable rename operation
- After download, checks magic bytes and renames if needed
- Handles collision resolution in `.jpg` namespace after rename (via `resolveFilenameCollision`)

**Files**: `google-photos-picker-downloader.ts`, `google-photos-picker-downloader.test.ts`
