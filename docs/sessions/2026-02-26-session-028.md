## Key Design Decisions

### createHeicPhashComputer

New function in `heic.ts` that returns a `PhashComputer` for HEIC files:
1. `readFile(filePath)` → raw bytes (injectable)
2. `decodeHeic({ buffer })` → `{ data: Uint8ClampedArray, width, height }` (injectable)
3. `sharp(Buffer.from(data.buffer), { raw: { width, height, channels: 4 } })` → resize 32×32, greyscale, raw
4. `dctHash(pixels, 32)` → pHash string
5. Returns `null` on any error (try/catch wraps everything)

No temp file, no double decode. `defaultHeicPhashComputer = createHeicPhashComputer()`.

### pHash stability across JPEG conversion

At 32×32 resolution, quality-90 JPEG compression does not change which side of the mean each DCT coefficient falls on. The pHash computed from raw HEIC pixels equals the one the indexer will compute from the quality-90 JPEG in the library.

### PlannerOptions.convertHeic removed

`convertHeic` was only used in `PlannerOptions` to inject a mock for the temp-file path during tests. The executor uses `ExecutorOptions.convertHeic` (separate interface), which is unchanged.

### Stability test deferred

No real HEIC fixture exists in `tests/fixtures/`. Stability test not added (deferred per task spec — correctness is established by pHash design properties).
