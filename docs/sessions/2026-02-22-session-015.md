# Session 015 — 2026-02-22

## Task
TASK-022 — Configure electron-builder for Windows (NSIS) + macOS (DMG)

## Goal
Produce working installers for Windows and macOS by completing the electron-builder
configuration: icon assets, native module handling, and CI compatibility.

## Architecture decisions

### No `postinstall` script
The spec suggested `"postinstall": "electron-builder install-app-deps"` to rebuild
native modules for the Electron ABI before packaging. This caused CI breakage:
- `npm ci` triggered `postinstall` → `better-sqlite3` compiled for Electron ABI 125
- Vitest tests run under Node.js (ABI 115) → `NODE_MODULE_VERSION` mismatch crash

**Decision**: remove `postinstall` entirely. `electron-builder` has `npmRebuild: true`
by default and rebuilds native modules automatically during `npm run package:win/mac`.
The postinstall was redundant for packaging and harmful for CI.

### `asarUnpack` kept as specified
Native `.node` files (`better-sqlite3`, `keytar`, `sharp`) must be outside the asar
archive at runtime. The `asarUnpack` config correctly handles this during packaging.

### `ci.yml` — plain `npm ci`
No workarounds needed. Without `postinstall`, `npm ci` installs native modules compiled
for Node.js (the default), which is exactly what the test runner requires.

## Deliverables

- `resources/icon.icns` — multi-size ICNS for macOS DMG (generated with electron-icon-builder)
- `scripts/generate-icons.mjs` — one-time sharp script used to produce the source PNG

### Modified files
- `package.json` — `asarUnpack`, `author: "MateoTTR"` (no `postinstall`)
- `.github/workflows/ci.yml` — reverted to plain `npm ci` (no workarounds needed)

## Key lesson
`electron-builder install-app-deps` (postinstall) is a **developer convenience** for
`npm start` in dev mode — not required for CI packaging. `electron-builder` rebuilds
native modules as part of `--win` / `--mac` automatically.
