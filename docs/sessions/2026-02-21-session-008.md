## Architecture retenue

### Découpage en 2 phases (validé en session)

**Phase 1 — Planning** (`buildImportPlan`) : aucune écriture
- Scan récursif du dossier source
- Filtre Live Photo MOVs
- Pour chaque fichier : pHash, EXIF date, check doublon DB, calcul destination, résolution collision
- Retourne un `ImportPlan` → affiché au renderer pour validation utilisateur

**Phase 2 — Exécution** (`executeImportPlan`) : après confirmation
- Staging temp → library write → DB upsert
- Annulation coopérative (entre chaque fichier)
- Nettoyage temp dir toujours exécuté (finally)
- Enregistrement `import_jobs`

### IPC channels

| Channel | Usage |
|---|---|
| `import:select-source-folder` | Dialog OS picker |
| `import:plan` | Invoke/reply bloquant — exécute Phase 1 dans un worker, retourne `ImportPlan` |
| `import:plan-progress` | Push progress Phase 1 |
| `import:execute` | Démarre Phase 2 en worker, retourne `{ started: true }` |
| `import:progress` | Push progress Phase 2 |
| `import:complete` | Push résultat final |
| `import:cancel` | Annulation coopérative |

### Gestion des doublons / collisions

| Cas | Comportement |
|---|---|
| pHash match dans la DB | `status = 'duplicate'` → skip en Phase 2 |
| Fichier destination existant | `status = 'collision'` → suffixe `_N` (max 99) |
| Aucun slot libre | `status = 'error'` → dans `ImportResult.errors` |
