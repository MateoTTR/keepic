### Specification refinements (v0.1 → v0.2)

| Topic | Decision |
|---|---|
| Platform | **Windows 10/11 + macOS** (Apple Silicon + Intel) — both first-class |
| Library folder | Raw photos only — **no DB, no thumbnails, no temp files** |
| Synology Drive | Library folder is sync-safe by design (clean file structure) |
| App data | Stored in OS standard dir (`%APPDATA%\KeePic\` / `~/Library/Application Support/KeePic/`) |
| Google Photos | Date filter: user specifies start date; incremental sync by Google ID |
| iPhone Live Photos | Keep HEIC, discard MOV by default; optional HEIC → JPEG conversion |
| Browse / view | **Deferred** — users use OS file explorer + native viewers in v1 |
| WhatsApp / Signal | Confirmed: folder scan only (no API integration) |

### ADR-001 — Desktop framework: **Closed → Electron**

Decisive factor: `sharp` (npm) provides cross-platform HEIC reading and conversion on both Windows and macOS with zero native dependency management. Tauri/Rust would require bundling `libheif` on Windows — unsolved complexity.

Tech stack confirmed:
- Electron + `electron-vite`
- TypeScript throughout (main + renderer + workers)
- `sharp` for image processing (HEIC, JPEG conversion, thumbnails)
- `better-sqlite3` for SQLite
- `keytar` for OS keychain
- `electron-builder` for packaging

### ADR-002 — Storage: **Closed → Filesystem + SQLite (app data dir)**

Key update: DB, thumbnails, and temp folder are stored in OS app data directory (not in library folder). Library folder is 100% clean for Synology Drive sync.
