# Session 033 — 2026-03-05

## Goal

Implement TASK-039: fix all HEIC handling issues by replacing ffmpeg with heic-decode v2.1.0,
add error reporting, and change default HEIC mode to 'keep'.

## Cross-format pHash testing

Before implementation, tested pHash compatibility on 20 real iPhone 12MP HEIC files:

| Comparison | Avg Hamming | Max | Result |
|---|---|---|---|
| heic-decode RGBA→gray vs JPEG→gray | 0.1 bits | 1 bit | Compatible — no JPEG intermediate needed |
| Tile 0 (ffmpeg) vs full image (heic-decode) | 32.6 bits | — | Completely different — confirmed bug |

heic-decode v2.1.0 performance: avg 393ms/file (vs 2-5s in v1.x) — ~10x improvement.

## Implementation

### Dependencies
- Removed `ffmpeg-static`
- Added `heic-decode@^2.1.0`
- Removed `node_modules/ffmpeg-static/**` from `build.asarUnpack`

### heic.ts — complete rewrite
- Removed all ffmpeg code (getFfmpegPath, SpawnFn, spawn-based operations)
- New `defaultHeicDecode(buffer)` using heic-decode v2.x API (`{ buffer }` not `{ data }`)
- New `createHeicConverter(decodeFn, readFile)` — heic-decode → sharp JPEG at native resolution
- Updated `createUniversalPhashComputer(options)` — HEIC: decode → sharp resize → dctHash
- Added `isHeicFile()` helper, `HeicDecodeFn` type, `HeicDecodeResult` interface

### Config spec change
- `AppConfig.heicConversion` → `AppConfig.heic: { mode: 'keep' | 'convert'; jpegQuality: number }`
- Default: `{ mode: 'keep', jpegQuality: 90 }`
- Backward compat: old `heicConversion.enabled` migrated in `mergeWithDefaults()`

### Error reporting
- Indexer: `IndexResult.errors` array, pHash failures caught and reported
- Importer: pHash/conversion failures set `status = 'error'` with `errorMessage`

### Tests
- 394 tests passing, 100% coverage, lint clean
- heic.test.ts completely rewritten (29 tests)
- All test files updated for new config shape

## Documentation updates
