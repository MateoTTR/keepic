## What was done

### TASK-V02 — Live Photo detection extensions
- Renamed `isLivePhotoMov` → `isLivePhotoVideo` (supports `.mov` AND `.mp4`)
- Added `isLivePhotoVideoExtension()` helper with `LIVE_PHOTO_VIDEO_EXTENSIONS` set
- Renamed `getHeicCandidatePaths` → `getPhotoCandidatePaths` (added `.jpg`, `.jpeg` siblings)

### TASK-V03 — Video-aware import pipeline
- Renamed `IMPORT_EXTENSIONS` → `IMPORT_MEDIA_EXTENSIONS` (added 7 video extensions)
- Phase 1: skip pHash computation for videos (`mediaType === 'video'`)
- Phase 2: video dedup by filename + file_size, photo dedup by pHash (unchanged)
- `upsertImportedPhoto`: added `mediaType` param and `media_type` SQL column

### TASK-V04 — Video-aware indexer + dedup scan + stats + thumbnails
- Renamed `IMAGE_EXTENSIONS` → `MEDIA_EXTENSIONS` (added 7 video extensions)
- Indexer Phase 1: computes `getMediaType()`, skips pHash for videos
- `library-stats-handler.ts`: SQLite `FILTER` clause separates photo/video counts
- `dedup-scan-handler.ts`: two queries — photo dedup (pHash) + video dedup (filename+size)
- `thumbnail.ts`: return type changed to `ThumbnailResult { buffer, contentType }`, SVG placeholder for videos
- `protocol.ts`: updated to use `result.buffer` and `result.contentType`

## Key decisions

- **Scan ordering**: Live Photo video check must come BEFORE importable media check, otherwise `.mov`/`.mp4` files are always treated as importable candidates
- **Video dedup strategy**: filename + file_size (no pHash) — consistent with existing design in task docs
- **ThumbnailResult**: changed return type from `Buffer` to `{ buffer, contentType }` to support SVG placeholders alongside JPEG thumbnails
- **SQLite FILTER clause**: confirmed working with better-sqlite3 for separating counts by media_type
