## Bugs found

### Bug #7 — Import still frozen on "Starting…" after TASK-026 (TASK-029, P0)

**Symptom**
After clicking "Import" on the review screen, the UI freezes on "Starting…".
The progress bar stays at 0. The Cancel button is unresponsive. App restart required.

**Root cause analysis (code review — 3 vulnerabilities)**

- **Cause A** — `db.open()` in `importer.worker.ts` is a synchronous call outside the
  Promise chain. If it throws, the `.catch()` does not catch it. The worker may crash
  silently without sending `{ type: 'error' }`, leaving the main process with nothing to
  forward → UI frozen.
- **Cause B** — No `worker.on('exit', ...)` handler in `handleExecute`. If the worker
  terminates without sending a message and without emitting 'error', `importerWorkerRef.value`
  stays non-null. The next import attempt returns `{ alreadyRunning: true }` silently.
- **Cause C** — `void window.keepic.import.execute(plan)` in `ExecutionScreen.svelte`
  silently discards the return value. If `execute()` returns `{ alreadyRunning: true }`
  or `{ error }`, or if the IPC invoke rejects, no `import:complete` is ever received →
  UI frozen indefinitely.

### Bug #8 — Google Photos 403 persists after disconnect/reconnect (TASK-028, P1)

**Symptom**
Even after disconnecting and reconnecting Google Photos, the "insufficient scopes" 403
error comes back on download. The user's Google Account shows access to email only, not
to the Photos library.

**Root cause**
The OAuth token exchange response includes a `scope` field listing the scopes *actually
granted* by Google. This field was not checked. If `photoslibrary.readonly` is absent
(consent screen misconfigured in Google Cloud Console, or user dismissed the Photos
permission), the token is still stored and the app incorrectly shows "connected". The 403
only surfaces at the first API call during download. Disconnect/reconnect stores the same
incomplete token again.
