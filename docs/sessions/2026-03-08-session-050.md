# Session 050 — 2026-03-08

## Goal

Implement TASK-048-feat: detect and exclude Live Photo video companions during library re-index.

## Context

After sessions 048–049 completed all Phase 16/17 tasks, the only remaining backlog item was TASK-048-feat (P3). The import pipeline already detected Live Photo companions (.mov/.mp4 paired with .heic/.jpg), but the library re-indexer did not — leading to inconsistent behavior if users manually copied Live Photo pairs into the library.

## Changes

### TASK-048-feat — Live Photo detection in re-index (PR #61, merged)

**`src/main/indexer.ts`**:
- Added post-scan pass in `scanLibraryFiles` after the main directory walk
- Builds a `Set` of all scanned file paths (lowercased) for O(1) sibling lookup
- For each `.mov`/`.mp4` file, checks if a photo sibling (`.heic`/`.heif`/`.jpg`/`.jpeg`) exists in the same folder
- Detected companions are removed from `files` and added to `skippedFiles` with `reason: 'live-photo'`
- Previously indexed companions are automatically removed via `markDeleted` on next re-index (standard behavior for files no longer in scan results)

**`src/renderer/src/screens/ReindexScreen.svelte`**:
- Added `livePhotoSkipped` derived state filtering `reason === 'live-photo'`
- New "Live Photo videos" collapsible section displayed before "Unrecognized extensions"
- Result summary now shows photo/video breakdown: `10 indexed (8 photos, 2 videos)`
- Added `indexedPhotos`/`indexedVideos` to the result type

**`tests/main/indexer.test.ts`** — 8 new tests:
- `scanLibraryFiles`: `.mov` + `.heic` sibling → excluded; `.mp4` + `.jpg` → excluded; standalone `.mov` → kept; cross-folder sibling → kept; case-insensitive detection; `.avi` not affected
- `runIndexer`: Live Photo pair → only photo indexed; previously indexed companion → marked deleted

## Test Results

- 520 tests pass (42 in indexer.test.ts)
- 100% coverage on all metrics (statements, branches, functions, lines)

## Decisions

- **Post-scan pass over Set** (not inline per-directory): simpler implementation, avoids per-directory state tracking, O(N) with Set lookup
- **Set-based sibling check** (not filesystem `existsSync`): faster, more predictable for testing, uses data already available from scan
