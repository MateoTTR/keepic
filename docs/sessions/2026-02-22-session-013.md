# Session 013 — 2026-02-22

## Task
TASK-020 — Implement standalone deduplication scan

## Goal
Allow users to scan the existing library index for photos that are already duplicated within the library (same pHash, different paths). Read-only report — no files deleted, no DB rows modified.

## Architecture decisions

### No worker thread
The scan is a single SQL aggregate query on an indexed column (`phash`). Fast even on large libraries — no worker thread needed. Same pattern as TASK-019 (library stats).

### Single SQL query + TypeScript grouping
One query fetches all non-deleted photos whose phash appears more than once, ordered by `phash ASC, imported_at ASC`. TypeScript groups the flat rows by phash using a `Map<string, DuplicatePhoto[]>`. Simple and efficient.

### Read-only contract
`handleScanDuplicates` makes no writes to the DB or filesystem. Users resolve duplicates manually (delete files → re-index via TASK-021).
