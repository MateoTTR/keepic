# Session 034 — 2026-03-05

## Task: PERF-001 — Concurrent processing + v0.2.2 release

### Summary

Implemented concurrent processing for the three heavy workflows (indexer, planner, executor) using a two-phase architecture: Phase 1 runs CPU-bound work in parallel (pHash, EXIF, HEIC staging, file copy), Phase 2 runs DB writes and progress reporting sequentially.

### Changes

1. **`src/main/concurrency.ts`** (new) — `withConcurrency<T,R>` async semaphore helper + `DEFAULT_CONCURRENCY` constant (`Math.min(os.cpus().length, 8)`)
2. **`src/main/indexer.ts`** — `runIndexer` split into Phase 1 (parallel stat + mtime check + pHash + EXIF) → Phase 2 (sequential DB upserts + progress)
3. **`src/main/importer.ts`** — `buildImportPlan` split into Phase 1 (parallel stat + pHash + EXIF + HEIC staging) → Phase 2 (sequential duplicate/collision checks + progress). `executeImportPlan` split into Phase 1 (parallel copy/convert/move) → Phase 2 (sequential DB upserts + progress). Added `seenDestPaths` set in planner Phase 2 for deterministic collision resolution under concurrency.
4. **`tests/main/concurrency.test.ts`** (new) — 8 tests for withConcurrency (order preservation, concurrency limiting, error propagation, edge cases)

### Key design decisions

- **No new worker threads**: existing worker threads already isolate CPU work. Parallelism comes from `Promise.all` within each worker — `sharp` (native) and `heic-decode` (WASM) both release the V8 lock.
- **`withConcurrency` is a simple worker-pool pattern**: N async workers pull items from a shared queue. No external dependency (p-limit).
- **Executor cancellation**: workers check `isCancelled()` at the start. No separate initial check — avoids consuming a call from the test mock.
- **Planner collision detection**: `seenDestPaths` Set tracks claimed destinations within the current plan, checked alongside filesystem existence in Phase 2 (sequential).
