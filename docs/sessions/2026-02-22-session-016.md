## Bug 1 — No library folder configuration UI (PR #18)

### Symptom
After installing the app, the user had no way to configure the library folder path.

### Root cause
`handleSelectLibraryFolder` IPC handler and `window.keepic.config.selectLibraryFolder()`
preload API existed and worked correctly, but no UI element called them. The `config`
object loaded in `App.svelte` (containing `libraryPath`) was never passed to `HomeScreen`.

### Fix
- `HomeScreen.svelte`: added `libraryPath` prop and a **Library folder** section
  showing the current path (or an amber warning if unconfigured) with a
  **Configure library folder…** / **Change…** button.
- `App.svelte`: pass `config?.libraryPath` to `HomeScreen`, add `handleLibraryPathChange`
  handler that updates the local config state.

After selecting a folder, stats are refreshed immediately via `window.keepic.library.getStats()`.

## Bug 2 — Google OAuth credentials silently undefined (PR #19)

### Symptom
Clicking "Connect Google Photos" showed the error *"Google OAuth credentials not configured"*.

### Root cause
`google-auth.ts` reads credentials via:
```typescript
clientId: (import.meta.env['GOOGLE_CLIENT_ID'] as string) ?? ''
```
`import.meta.env` is populated **at build time** by electron-vite. electron-vite only
exposes env vars that match a configured prefix. The default prefix for the main process
is `MAIN_VITE_`. Because `GOOGLE_CLIENT_ID` does not start with `MAIN_VITE_`, it was
always `undefined` — both in local dev builds and in CI release builds — regardless of
whether the variable was set in the environment or `.env` file.

### Fix
Added `GOOGLE_` to the `envPrefix` list for the main process in `electron.vite.config.ts`:
```typescript
main: {
  envPrefix: ['MAIN_VITE_', 'GOOGLE_'],
  ...
}
```
No renaming of variables in code, `.env`, or CI workflow required.

## Bug 3 — Installer filename showed 0.1.0 instead of 0.1.1

### Root cause
electron-builder uses `version` from `package.json` for the installer filename,
not the git tag. `package.json` was still at `"version": "0.1.0"`.

### Fix
Bumped `package.json` version to `"0.1.1"`, re-created the `v0.1.1` tag on the new commit.

## Key lessons

- **electron-vite envPrefix**: env vars for the main process must have the `MAIN_VITE_`
  prefix (or a custom prefix configured in `envPrefix`) to be accessible via
  `import.meta.env`. Variables without a matching prefix are silently `undefined`.
- **electron-builder installer filename**: comes from `package.json` `version`, not
  from the git tag. Always bump `package.json` before tagging a release.
- **Complete the UI wire-up**: IPC handlers and preload APIs have no value if no UI
  element calls them. Check end-to-end from button → preload → IPC → handler.
