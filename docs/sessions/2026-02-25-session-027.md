## Key Design Decisions

### Integration test structure

`tests/main/integration/google-picker-flow.test.ts` exercises the real handler code
(no mocking of internal modules) with four test groups:

1. **Happy-path flow**: `handleCreatePickerSession` → `handlePollPickerSession` ×2
   (false then true) → `handleStartPickerDownload` → worker progress events → complete
2. **Error scenarios**: not authenticated (all handlers), 401 token expired (create + poll),
   already running
3. **Cancellation flow**: cancel message → worker responds with `status: 'cancelled'`
4. **Download failure**: worker error message, partial download with per-file errors

The `makeIntegrationDeps` helper builds a full `PickerHandlerDeps` with a real in-memory
keytar store and a URL-keyed fetch mock (explicit `null` = no token stored).

The `makeWorkerFactory` and `makeFakeWorker` helpers simulate the worker thread using
`EventEmitter` — the same pattern used in unit tests.

### Error message improvement

`toUserFacingError()` helper added to `google-photos-handlers.ts`: maps the internal
`'Token expired'` sentinel (used by the downloader for auto-refresh detection) to
the user-facing string `'Your Google session has expired. Please disconnect and reconnect
to continue.'` — without changing the sentinel in `google-photos-picker.ts` (which would
break the downloader's refresh logic).

### Notes on progress event structure

The `spawnPickerDownloadWorker` passes the raw worker message to `onProgress` and
`onComplete`, which means they include the `type: 'progress'` / `type: 'complete'` field.
Tests use `toMatchObject` to check only the relevant fields.
