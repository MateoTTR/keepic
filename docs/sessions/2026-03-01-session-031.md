# Session 031 — 2026-03-01

## Goal

Implement TASK-037 (P0): replace the WASM HEIC decoder (`heic-decode`/`libheif-js`) with `ffmpeg-static` (native pre-built binaries) to eliminate the 2-WASM-decode-per-file bottleneck (~4–10s/file → ~0.5s/file).

## What was done

### Branch

`feature/TASK-037-fix-heic-double-decode` (branched from `develop`)

### Dependencies

- Removed: `heic-decode`, `libheif-js`
- Added: `ffmpeg-static ^5.3.0`
- Deleted: `src/main/heic-decode.d.ts` (orphaned type declaration)

### `src/main/heic.ts` — full rewrite

Removed WASM-based code (`createHeicPhashComputer`, `defaultHeicPhashComputer`, `HeicPixelDecoder`).

Added:
- **`getFfmpegPath(loadPath?)`**: resolves the ffmpeg binary path; injectable `loadPath` for testing the null-platform branch; rewrites `app.asar` → `app.asar.unpacked` for production (Electron packaged app)
- **`SpawnFn` type**: `(command, args) => EventEmitter` — injectable child_process.spawn for tests
- **`createHeicConverter(ffmpegPath, spawnFn?)`**: ffmpeg-based HEIC→JPEG conversion (`-q:v` quality, `-y` overwrite)
- **`createUniversalPhashComputer(ffmpegPath, options?)`**: routes by extension:
  - `.heic` / `.heif`: ffmpeg → temp JPEG → native sharp pHash → delete temp
  - all others: native sharp directly (no ffmpeg)

Cleanup pattern: replaced `try-catch-finally` with explicit cleanup after try-catch to avoid a v8 async instrumentation branch artifact on the `} finally {` line.

### `src/main/indexer.ts`

Changed the default `computePhash` option from `defaultPhashComputer` to `createUniversalPhashComputer(getFfmpegPath())`. HEIC files in the library now receive a real pHash in the DB (previously always null, so HEIC deduplication was broken).

### `src/main/importer.ts`

**Planner** (`buildImportPlan`):
- `PlannerOptions`: removed `computeHeicPhash?`, added `convertHeic?`, `stagingDir?`, `mkdirp?`
- HEIC + conversion enabled: runs ffmpeg once → staged JPEG in `stagingDir`; computes pHash from staged JPEG (native sharp); stores `entry.stagedPath`
- HEIC + conversion disabled (or non-HEIC): original `computePhash(srcPath)` path

**Executor** (`executeImportPlan`):
- `ExecutorOptions`: added `rmStagedFile?`
- Entry with `stagedPath`: move staged JPEG directly to library (no re-decode)
- Cleanup: after processing (success or failure), delete any remaining staged files

### `src/shared/types/index.ts`

Added `stagedPath?: string` to `ImportPlanEntry` (internal staging path, not displayed in UI).

### `package.json`

Added `node_modules/ffmpeg-static/**` to `asarUnpack` so the binary is executable outside the asar archive at runtime.

## Key design decisions

- **Staging pattern**: 1 ffmpeg call in planner → staged JPEG → executor moves (no re-decode). Cleaner and faster than 2× ffmpeg calls.
- **SpawnFn injectable**: avoids spawning real ffmpeg in unit tests; `convertHeicToJpeg` default test uses real ffmpeg (expects rejection on invalid input).
- **Universal phash computer**: single function handles all formats; replaces the split between `defaultPhashComputer` (non-HEIC) and `defaultHeicPhashComputer` (HEIC).
- **v8 coverage artifact**: `} catch {}` inside async `finally` creates an uncoverable synthetic branch. Fixed by restructuring to explicit cleanup after try-catch (no `finally` block needed).
