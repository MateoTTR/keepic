### Key Discovery: WASM Concurrency Limitation

PERF-001's `withConcurrency` creates N async workers in a single Worker thread.
This is effective for I/O-bound work (network, filesystem) and native code (sharp uses libuv thread pool),
but WASM execution (heic-decode) blocks the V8 event loop. All HEIC decodes run sequentially
despite the concurrency wrapper. True parallelism requires N separate Worker threads (PERF-002).

Updated ADR-005, backlog Phase 9 note, and created Phase 11 for the fix.
