## Decisions Made

### Multi-user shared library
The library folder is shared by multiple users (all using the app). Each instance is independent:
- **Append-only policy**: the app never modifies or deletes existing files in the shared folder
- **Per-instance local index**: each user's app builds its own SQLite DB by scanning the shared folder
- Recommended workflow before import: sync Synology Drive → re-index → import

### Folder naming convention (breaking change from v0.2)
Previous convention (`YYYY/MM/DD/`) is replaced by:
- Year folders: `YYYY` (only these are scanned; all other root-level folders ignored)
- Monthly folders: `YYYY.MM` (created by the app on import)
- Event folders: `YYYY.MM.DD[-[MM.]DD].EventName` (created **manually** by users in V1)
- New photos always land in the **monthly folder** for their capture date

### Testing & CI/CD
- **100% test coverage** on all non-frontend code (main process, workers, shared utilities)
- Tests must cover production code — no mocking of internal modules
- **GitHub Actions CI/CD**: lint + type-check + tests + coverage gate on every PR
- Release builds (Windows NSIS + macOS DMG) triggered on `main` tags

### Git Flow
Branching strategy:
- `main` → production only
- `develop` → integration
- `feature/TASK-NNN-*` → one branch per task, targeting `develop`
- `release/vX.Y.Z` and `hotfix/*` as needed

### Google Photos — additional clarifications
- Each user authenticates independently via OAuth 2.0
- Start date filter on `creationTime`
- **App remembers last import date**: pre-fills start date on subsequent imports (Q4 closed)
