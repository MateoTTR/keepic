## Décisions techniques

### Serveur HTTP callback — architecture sans double création

La spec initiale fermait un premier serveur pour obtenir le port, puis en recréait un sur le même port. Pattern remplacé par `startCallbackServer()` : un seul serveur créé, port lu après `server.listen(0)`, timeout géré dans la même instance.

### Tests — race condition sur rejection de promesse

Problème : dans les mocks `openBrowser`, `await fetch(callbackUrl)` déclenchait la rejection de `callbackPromise` avant que `startOAuthFlow` ne l'attende. Solution : `void fetch(...)` (fire-and-forget) dans les mocks, et `Promise.all([fetch(...), expect(promise).rejects.toThrow(...)])` pour les tests de `startCallbackServer` qui testent les cas d'erreur.

### Coverage 100% — branches `??`

Les opérateurs `??` sur les deps par défaut (`?? defaultKeytarGet`, `?? DEFAULT_CREDENTIALS`, etc.) requièrent des tests appelant les fonctions sans passer les deps correspondantes. Keytar et Electron étant mockés globalement avec `vi.mock`, les defaults sont testables. La branche `req.url ?? '/'` (impossible à déclencher via HTTP) est exclue avec `/* v8 ignore next */`.

### `vite/client` dans tsconfig.node.json

`import.meta.env` n'était pas reconnu par TypeScript dans le processus main. Solution : ajouter `"vite/client"` aux `types` de `tsconfig.node.json`.
