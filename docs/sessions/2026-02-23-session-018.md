## Bugs found

### Bug #4 — Import frozen on "Starting…" (TASK-026, P0)

**Symptom**
After clicking "Import" on the review screen, the UI freezes on "Importing…" /
"Starting…". The progress bar never moves and no files are copied to the library.

**Root cause**
Race condition: `execute()` is called in `App.svelte`'s `handleImport()` synchronously,
before Svelte mounts `ExecutionScreen` and its `onMount` registers the `onProgress` /
`onComplete` IPC listeners. If the worker fails immediately, the `import:complete` event
is fired before the listener exists → event silently dropped → UI frozen forever.
Secondary issue: `ipcRenderer.on()` listeners are never removed on component destroy.

### Bug #5 — Cancel frozen on "Cancelling…" (TASK-026, P1 — cascade of Bug #4)

**Symptom**
Clicking "Cancel" on the execution screen freezes the UI on "Cancelling…". App restart
required.

**Root cause**
`handleCancel` does `activeWorkerRef.value?.postMessage(...)`. If no worker is running
(Bug #4 scenario), this is a no-op → no `import:complete` event is ever sent → UI stuck.
Same issue in `handleCancelDownload` for Google Photos.

### Bug #6 — Google Photos 403 "insufficient authentication scopes" (TASK-027, P1)

**Symptom**
After launching a Google Photos download:
`Google Photos API error: 403 — Request had insufficient authentication scopes.`

**Root cause**
The stored OAuth token was issued before `photoslibrary.readonly` was properly configured
in the Google Cloud Console OAuth consent screen. Re-authorising (Disconnect → Connect)
should resolve it. Code fix: surface a user-friendly error message instead of the raw
403 JSON.

## Feature request

### FEAT-001 — Side-by-side duplicate comparison viewer

When two duplicate photos are detected, the user wants to view them side by side with
metadata (filename, date, size, dimensions, source) to decide which copy to keep. A
"Reveal in Explorer/Finder" button would allow manual deletion before re-indexing.
Architectural note: requires a custom Electron protocol or base64 IPC to display local
images in the sandboxed renderer.

## Observations

- Deduplication scan works correctly: two photos (original HEIC + WhatsApp re-encoded
  JPEG with different filename) were correctly identified as visual duplicates.
- pHash is a perceptual (DCT-based) hash → format-agnostic, robust against JPEG
  re-encoding. False positive risk is negligible for personal libraries (< 1 in 10M
  at 100k photos with exact 64-bit matching).
- Current HEIC pre-conversion in the planner (HEIC → temp JPEG → pHash) is unnecessary
  since Sharp handles HEIC natively. Noted as REFACTOR-001.
- Indexing felt slow on SSD for 900 photos. Root cause: single-threaded sequential
  processing. Noted as PERF-001.
