## Bugs found and documented

### TASK-037 — HEIC slow processing (P0)
Root cause: v0.2.0 triggers `heic-decode` (WASM/libde265) **twice** per HEIC file:
1. Planner: `createHeicPhashComputer` → WASM decode → pHash
2. Executor: `createHeicConverter` → WASM decode → JPEG

~2-5s per WASM decode → 4-10s per file. Unacceptable for large HEIC collections.

Observation: the library indexer (using native sharp) is fast on HEIC because sharp fails
silently → no WASM involved. The slowness is entirely in the import pipeline.

**Chosen solution**: Replace `heic-decode` with `ffmpeg-static` (pre-built native binaries).
- 1 ffmpeg call in planner: HEIC → staged JPEG → pHash from JPEG (native sharp)
- Executor: move staged JPEG to library (no re-decode)
- New field `stagedPath` in `ImportPlanEntry`
- Duplicate detection preserved ✅
- ~0.5s/file vs 4-10s/file (10-50× speedup)
- Requires `asarUnpack` in electron-builder + runtime path resolution

Full design: [docs/tasks/TASK-037-fix-heic-double-decode.md](../tasks/TASK-037-fix-heic-double-decode.md)

### TASK-038 — Picker API list URL 404 (P1)
`listPickerMediaItems` constructs the wrong URL: `sessionId` is used as a path segment
instead of a query parameter.

```
// Wrong (produces 404)
GET /v1/sessions/{sessionId}/mediaItems?pageSize=100

// Correct
GET /v1/mediaItems?sessionId={sessionId}&pageSize=100
```

2-line fix in `src/main/google-photos-picker.ts` + update URL assertions in tests.

Full design: [docs/tasks/TASK-038-fix-picker-list-url.md](../tasks/TASK-038-fix-picker-list-url.md)
